# Лимиты бесплатных тарифов (Free Tier Limits)

**Дата проверки по официальной документации:** 18 ноября 2026 г.

Поскольку проект имеет нулевой бюджет (только бесплатные тарифы, без привязки карт для оверейджей), все архитектурные решения строго укладываются в указанные ниже квоты.

---

## 1. Vercel (тариф Hobby — Free)

Источник: официальная документация Vercel Limits (`vercel.com/docs/limits`).

| Параметр | Лимит на тарифе Hobby | Влияние на наш проект и как мы укладываемся |
|---|---|---|
| **Fast Data Transfer (исходящий трафик CDN)** | **100 ГБ / месяц** | Аудио (mono MP3 32–48 кбит/с) и JSON юнитов кэшируются в браузере через Service Worker / Cache Storage и `Cache-Control: public, max-age=31536000, immutable`. Повторные прослушивания не расходуют трафик CDN. |
| **Fast Origin Transfer** | **10 ГБ / месяц** | Публичные страницы юнитов генерируются статически (SSG), игровой плеер работает на клиенте, обращения к серверным функциям минимальны. |
| **CDN Requests** | **1 000 000 запросов / месяц** | Кэширование ассетов в PWA снижает число повторных HTTP-запросов к CDN. |
| **Serverless Function Invocations** | **1 000 000 вызовов / месяц** | Синхронизация прогресса идёт напрямую из браузера в Supabase по `anon`-ключу + RLS, минуя Serverless Functions Vercel. |
| **Размер одного статического файла** | **100 МБ** | Наши MP3-клипы весят 10–40 КБ, JSON юнита ≤ 40 КБ. |
| **Размер бандла Serverless-функции** | **250 МБ (uncompressed)** | Статические ассеты в `public/audio/` раздаются через CDN и не включаются в бандл серверных функций. |
| **Время сборки (Build Time)** | **45 минут** на деплой | Контент (`content/`) и аудио (`public/audio/`) уже собраны и закоммичены в Git; при билде на Vercel не выполняется генерация TTS. |
| **Назначение тарифа** | **Только некоммерческое использование** | Проект полностью бесплатный, без монетизации и рекламы — полностью соответствует правилам Hobby. |

## 2. Supabase (тариф Free)

Источник: официальная документация Supabase Pricing & Limits (`supabase.com/pricing`, `supabase.com/docs/guides/platform`).

| Параметр | Лимит на тарифе Free | Влияние на наш проект и как мы укладываемся |
|---|---|---|
| **Размер базы данных PostgreSQL** | **500 МБ** | В Supabase хранятся **только** профили и компактные записи прогресса (`profiles`, `unit_progress`, `review_state`, `daily_activity`, `content_feedback`). Контент курсов и аудио в Supabase не хранятся. 500 МБ хватит на десятки тысяч активных учеников. |
| **Активные бесплатные проекты** | **2 проекта** на организацию | Нам требуется только 1 проект (регион `eu-central-1` / Frankfurt или ближайший европейский). |
| **Monthly Active Users (MAU)** | **50 000 MAU / месяц** | Более чем достаточно; кроме того, гостевой режим работает вообще без создания записи в Supabase Auth. |
| **Исходящий трафик (Egress)** | **5 ГБ / месяц** | Передаются только короткие JSON-пакеты дельты прогресса при синхронизации. |
| **Встроенный SMTP (отправка писем Auth)** | **2 письма в час**, и только на адреса участников команды проекта (`team members`) | **Критическое ограничение!** Встроенный SMTP Supabase предназначен только для разработки и не доставляет письма внешним пользователям. Решения описаны в `docs/DECISIONS.md` (раздел 3) и `docs/USER_ACTIONS.md`: 1) Вход через Google OAuth (не требует писем); 2) Отключение обязательного `Confirm email` для быстрого входа по email+пароль либо подключение бесплатного внешнего SMTP (например, Resend Free — 3 000 писем/мес, 100 писем/день, или Brevo Free — 300 писем/день). |
| **Приостановка проекта (Project Pausing)** | **Пауза после 7 дней отсутствия запросов к БД** | Supabase учитывает именно запросы к PostgreSQL. Мы: 1) делаем приложение полностью работоспособным офлайн и в гостевом режиме (даже если Supabase недоступен); 2) добавляем на Этапе 6 GitHub Action (`keepalive.yml`), который каждые 3 дня делает `SELECT id FROM public.healthcheck LIMIT 1`. |

## 3. GitHub (тариф Free)

Источник: официальная документация GitHub Repositories & Actions Limits (`docs.github.com`).

| Параметр | Лимит на тарифе Free | Влияние на наш проект и как мы укладываемся |
|---|---|---|
| **Жёсткий лимит размера одного файла** | **100 МБ** (предупреждение от 50 МБ) | Отдельный MP3-файл весит ≤ 40 КБ, JSON юнита ≤ 40 КБ. Git LFS не используется. |
| **Рекомендуемый размер репозитория** | **До 1 ГБ** (желательно значительно меньше) | Наш целевой бюджет на всё аудио обоих курсов (2 500–3 500 клипов в mono MP3 32–48 кбит/с) — **≤ 60 МБ** (жёсткий потолок **100 МБ**). Вместе с кодом весь репозиторий уложится в ~80–110 МБ. |
| **GitHub Actions (CI/CD минуты)** | **Безлимитно** для публичных репозиториев; **2 000 минут / месяц** (Linux) для приватных | CI-пайплайн (`lint`, `typecheck`, `test`, `content:check`, `build`, `gitleaks`) с кэшированием `pnpm` занимает ~1,5–2 минуты на запуск. |
| **GitHub Actions Cache** | **10 ГБ** на репозиторий | Используется для кэша `pnpm store` и `.next/cache`. |

## 4. Google Gemini API / Gemini TTS (Google AI Studio)

Источник: документация Google AI for Developers (`ai.google.dev/gemini-api/docs/rate-limits`, `ai.google.dev/gemini-api/docs/speech-generation`).

| Параметр | Лимит на тарифе Free (AI Studio) | Влияние на наш проект и как мы укладываемся |
|---|---|---|
| **Модель TTS** | Семейство `gemini-2.5-flash-preview-tts` (и актуальные TTS-модели в Google AI Studio) | Вызывается **только локально** скриптом `scripts/tts/generate.ts` на компьютере владельца. На сайте в рантайме вызовов к Gemini нет. |
| **Частота запросов (RPM / RPD)** | Free tier для preview TTS: ориентировочно **до 10 RPM** и строгий дневной лимит (RPD) | Скрипт генерации аудио (`scripts/tts/generate.ts`) реализуется полностью **идемпотентным и возобновляемым** по хэшу `(text + voice + style + model)` в `content/audio-manifest.json`, с настраиваемой паузой между запросами (rate-limiter) и экспоненциальным backoff при `429 RESOURCE_EXHAUSTED`. Генерацию 2 500–3 500 клипов можно проводить батчами по секциям без потери уже созданных файлов. |
| **Токены на запрос** | До 8 192 входных / 16 384 выходных токенов | Мы генерируем короткие клипы (одно слово или одна реплика одним голосом), что укладывается в доли секунды/несколько секунд аудио на запрос. |
