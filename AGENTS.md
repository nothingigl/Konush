# AGENTS.md — Правила разработки проекта «Türkçe Duo» (рабочее название)

Этот файл фиксирует обязательные правила работы ИИ-агента между сессиями. Все решения и ограничения здесь являются источником правды.

## 1. Процесс разработки и Gate-проверки

1. **План перед кодом:** На каждом этапе сначала составляется `Implementation Plan` по текущему этапу. Написание кода начинается **только после явного подтверждения («ОК»)** от владельца проекта.
2. **Этапы и Gate:** В конце каждого этапа стоит **Gate**. Агент останавливается, формирует самодостаточный пакет проверки `reviews/gate-N.md` (размер до ~30 тыс. слов, лучше компактнее) и ждёт слова **«Принято»**. Самостоятельный переход к следующему этапу запрещён.
3. **Самодостаточность `reviews/gate-N.md`:** Внешний ревьюер (Claude) не имеет доступа к репозиторию. Поэтому каждый `reviews/gate-N.md` обязан содержать:
   - Что сделано на этапе;
   - Полный список добавленных/изменённых файлов;
   - Инструкцию по локальному запуску и проверке;
   - Выводы тестов, линтера, проверки типов и сборки;
   - Известные проблемы и ограничения;
   - **Вопросы к владельцу проекта**;
   - Раздел **«Что проверить Claude»** с вставленными прямо в документ ключевыми фрагментами кода, SQL-миграциями, схемами и текстами.
4. **Пакеты контента:** На Этапе 4 контент отдаётся на ревью отдельными файлами по секциям `reviews/content/<course>-section-N.md` (слова + все упражнения человекочитаемо с переводом и ключом).
5. **Языковая политика:**
   - Код, комментарии в коде, идентификаторы, имена файлов/переменных и сообщения коммитов — **на английском** (`Conventional Commits`: `feat:`, `fix:`, `docs:`, `chore:`, `test:`).
   - Интерфейс сайта (`messages/ru.json`), документация в `docs/` и отчёты в `reviews/` — **на русском**.
6. **Git-поток:**
   - Одна ветка на этап (`feat/stage-N-...`), слияние через Pull Request в `main`.
   - Запрещено пушить напрямую в ветку `main`.
   - Запрещено использовать Git LFS.
7. **Никаких догадок:**
   - Если данных не хватает или возникает неоднозначность — задать вопрос в `reviews/gate-N.md` или напрямую владельцу, а не додумывать.
   - Любое отступление от мастер-промпта фиксируется в `docs/DECISIONS.md` с обоснованием и ждёт подтверждения владельца.

## 2. Продуктовые и архитектурные инварианты

1. **Бюджет 0 ₽ / $0:** Только бесплатные тарифы (Vercel Hobby, Supabase Free, GitHub Free). Никакой монетизации, никаких сторонних трекеров.
2. **Два курса для русскоязычных:**
   - `tr` (турецкий: 67 юнитов + 3 босса в 3 секциях).
   - `en` (английский: 60 юнитов + 3 босса в модулях 1–3; архитектура заложена под модули 4–8 до 295 юнитов).
3. **Профили и синхронизация:**
   - Локальная БД в браузере (IndexedDB через `Dexie`) — первичный источник правды для UI (мгновенная работа и офлайн-режим).
   - Гостевой режим работает полностью без регистрации; при регистрации/входе локальный прогресс переносится и сливается с облачным профилем.
   - Облачная синхронизация через Supabase (`@supabase/supabase-js`, `@supabase/ssr`).
4. **Озвучка (TTS):**
   - 4 персонажа-голоса (2 женских, 2 мужских) с эмоциональными стилями.
   - Всё аудио генерируется заранее локальным скриптом (`scripts/tts/generate.ts`) через Gemini TTS и хранится в репозитории (`public/audio/{tr,en}/<unit>/<id>.mp3`, манифест `content/audio-manifest.json`).
   - **Сайт в рантайме никогда не обращается к Gemini API.**
5. **Бренд:** Не использовать название, логотип, сову или ассеты Duolingo. Рабочее название «Türkçe Duo» будет заменено на финальное имя на Gate 3.

## 3. Разделение хранения: GitHub vs Supabase vs Vercel

### В GitHub хранятся:
- Код приложения (`src/`, `public/`), исходники курса (`content-src/*.md`), проверенный JSON-контент (`content/courses/{tr,en}/`), сгенерированное mp3-аудио (`public/audio/`), манифест (`content/audio-manifest.json`), скрипты (`scripts/`), SQL-миграции (`supabase/migrations/*.sql`), дизайн (`design/`), документация (`docs/`, `reviews/`), `.env.example`.
- **Никогда не коммитить в Git:** `.env*` с реальными значениями, `GEMINI_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, пароли БД, сырые WAV/PCM-файлы (`tmp/`), `node_modules/`, `.next/`, пользовательские данные.

### В Supabase хранятся ТОЛЬКО пользовательские данные:
- `auth.users`, `public.profiles`, `public.unit_progress`, `public.review_state`, `public.daily_activity`, `public.content_feedback`, служебная `public.healthcheck`.
- Вся схема управляется исключительно через `supabase/migrations/*.sql`.
- На всех таблицах включён **RLS**. Клиент использует только публичный `anon` ключ. Удаление аккаунта — через `security definer` RPC `delete_my_account()`.
- В Supabase **не хранятся** контент курсов, аудиофайлы, ключи Gemini и записи микрофона пользователя.

## 4. Правила работы с контентом (Zero-Trust Rule)

1. **Никогда не «исправлять» турецкий или английский учебный текст по памяти молча.** Любое изменение относительно исходных `.md` файлов фиксируется в `docs/CONTENT_CHANGELOG.md`.
2. Все задания из исходных файлов помечаются `"origin": "source"` и обязаны войти в юнит. Дополнительные упражнения до объёма 8–12 на навык помечаются `"origin": "derived"` и используют только лексику текущего и предыдущих юнитов.
3. Каждое из 12 слов юнита (11 в `tr-2-3`) должно встречаться минимум в 2 упражнениях юнита.
4. Повторение юнитов строго по расписанию **1 → 3 → 7 → 14 дней**.
5. В production-сборку попадают только юниты со статусом `"review": "claude_ok"` (статус меняется только по команде владельца «секция X проверена»).
